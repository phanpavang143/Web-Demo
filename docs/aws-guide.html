AWS deployment / project WebDemo

From local build to private ECS tasks.

This page summarizes the deployment path. The repository README remains the source of truth for every Terraform variable and operational detail.

01

Authenticate

Use IAM Identity Center or SSO. Never commit access keys.

aws sso login --profile my-aws
$env:AWS_PROFILE = "my-aws"
aws sts get-caller-identity
02

Prepare secrets

Create an AWS Secrets Manager JSON secret with db_driver, db_url, db_username, and db_password. Terraform passes these to ECS without putting them in the image.

03

Provision

Terraform creates the VPC, private ECS service, ALB, ECR, S3, SQS, CloudWatch, Lambda, EventBridge, and CloudTrail resources.

cd infrastructure/terraform
terraform init
terraform validate
terraform apply -var-file=variables.tfvars
04

Ship the image

Build the Java 25 image, push it to ECR, then update the ECS task definition with its immutable tag.

docker build -t jt-spring-commerce:latest .
docker push <account>.dkr.ecr.<region>.amazonaws.com/<repo>:latest
05

Verify

The ALB health check is public and expects HTTP 200 from /actuator/health. Check CloudWatch logs when a task is unhealthy.

terraform output -raw load_balancer_url
curl <load-balancer-url>/actuator/health
06

Operate

Product images stay private in S3, order events go to SQS, metrics go to CloudWatch, and ECS uses IAM roles instead of static keys.

Important: Terraform does not create MySQL/RDS. Supply a reachable MySQL endpoint through the Secrets Manager secret before deploying the application image.
